# Test Scenarios

这个文档用于固定第一版测试范围。

对于 Zama / FHEVM 教程来说，测试不仅是质量保障工具，也是帮助读者理解数据流和权限边界的教学工具。

## 第一批必须覆盖的场景

### 1. 初始化成功

验证点：

- 投票标题正确
- 候选项数量正确
- 开始和结束时间正确
- 初始状态下没有人投票

### 2. 用户可以成功投票

验证点：

- 在有效时间内可以提交投票
- 交易成功
- `hasVoted` 状态更新为 `true`

### 3. 用户不能重复投票

验证点：

- 同一地址第二次投票会失败
- 已投票状态不会被错误覆盖

### 4. 投票时间窗口生效

验证点：

- 开始前不能投票
- 结束后不能继续投票

### 5. 结果公开时机正确

验证点：

- 结束前不能读取最终公开结果
- 结束后可以进入结果公开阶段

## 第一版可以暂缓的测试

- 多用户并发复杂交互
- 极端候选项数量
- 复杂前端联调场景
- 测试网真实加密路径

这些都可以放到第二阶段，否则教程节奏会变重。

## 推荐测试顺序

1. 先写公开状态和时间窗口测试
2. 再写投票成功和重复投票失败
3. 最后再补结果公开阶段测试

这样测试会和合约开发节奏更一致。
