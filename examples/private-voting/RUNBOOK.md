# Private Voting Runbook

这份 runbook 面向第一次跑这个示例的读者，目标是帮你用“本地优先”的方式把整个案例串起来。

## 推荐顺序

1. 先安装依赖
2. 再编译合约
3. 再运行测试
4. 再启动本地链
5. 再部署合约
6. 最后打开前端页面

不要一上来就跳到测试网。  
这套教程默认先把本地闭环跑顺。

## 1. 安装依赖

进入目录：

```bash
cd /Users/mudimu/mudi/web3/rochestor/zama-tutorial-cn/examples/private-voting
```

安装依赖：

```bash
npm install
```

## 2. 编译合约

```bash
npm run compile
```

如果这里失败，先检查：

- Node.js 版本是否合适
- 依赖是否完整安装

## 3. 运行测试

```bash
npm test
```

当前示例至少应看到测试通过，说明最小合约逻辑在 mock 环境里是通的。

## 4. 启动本地链

新开一个终端窗口，在同一目录下运行：

```bash
npm run chain
```

这会启动本地 Hardhat 节点。

## 5. 部署合约

再开一个新终端窗口，在同一目录下运行：

```bash
npm run deploy:localhost
```

记下输出中的合约地址。  
前端页面会用到它。

## 6. 启动前端静态页面

再开一个终端窗口，在同一目录下运行：

```bash
python3 -m http.server 4173
```

然后打开：

```text
http://localhost:4173/frontend/
```

## 7. 在前端里做什么

进入页面后：

1. 连接 MetaMask
2. 确保钱包连的是本地链
3. 粘贴刚才部署得到的合约地址
4. 读取公开状态
5. 观察投票阶段、候选项和结果状态

在本地链模式下，这个前端主要用于：

- 展示公开状态
- 演示 owner 操作
- 对照教程理解状态流转

## 关于 Sepolia

Sepolia 不是这套教程的默认必做项。

如果你后面想继续验证：

- 浏览器端加密投票输入
- 浏览器端结果解密

可以自行把合约部署到 Sepolia，再继续做真实网络联调。

这里刻意不提供预部署地址，是为了让读者自己掌握部署过程，而不是依赖一份随时可能失效的共享地址。
